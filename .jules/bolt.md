## 2026-10-04 - Merkle Tree & Hash Pair Allocation Optimization
**Learning:** `BuildMerkleTree` and `HashPair` in Merkle proof generation created significant heap allocation overhead due to dynamic slice appends in `HashPair` (`append(lBytes, rBytes...)`), repeated `hex.DecodeString`/`hex.EncodeToString`, and slice merging for leaf index tracking at every level of the tree. Using stack-allocated 64-byte array buffers for SHA-256 inputs, custom zero-allocation hex decoding/encoding, and leaf range tracking (`[start, end]`) reduced Merkle tree construction time by ~2.7x (3.8ms -> 1.4ms for 1024 leaves) and allocations by ~70% (10,363 -> 3,101 allocs/op).
**Action:** When performing crypto digest hashing over hex strings in high-frequency batch loops (like Merkle trees or status lists), use fixed-size stack array buffers and range-based index tracking instead of allocating dynamic slices.
